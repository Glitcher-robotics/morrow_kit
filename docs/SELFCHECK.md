# SELFCHECK — 3+1축 자가 점검 (기술·의도·인지 + 소통)

점수는 "했다"가 아니라 **AI 대화·터미널·git·문서에 남았다**로 받는다는 가정으로 점검한다. 축과 세부 항목 이름은 공개된 평가 구조 기준이고, 세부 배점·판정 방식은 공식이 아니다.
표기: **[기술]** Technique · **[의도]** Intent · **[인지]** Cognition · **[소통]** Communication(FDE 트랙, 배점 미공개).
사용법: ① 프롬프트 보내기 전 30초(1절) ② 체크포인트마다 2분(2절) ③ 155분에 축별 O/X(3절). 빈칸은 다음 프롬프트에서 바로 채우고, 체크를 채우려고 기록을 지어내지 않는다.

## 0. 점수 전략 — 어디에 힘을 줄까

| 축 | 특징 | 전략 |
|---|---|---|
| **의도** | 변별력이 가장 컸던 축 | **매 프롬프트를 같은 틀로**: 범위·근거 D·내 예상·멈출 조건·증거. 틀의 반복 자체가 "작업 체계" 증거다 |
| **인지** | 전원이 가장 낮았던 축 → 조금만 해도 차별화 | 실행 전 **내 예상**, 직접 읽고 **내 말로 설명**, "**왜·대안**" 질문, 반박 흔적을 대화에 남긴다 |
| **기술** | 결과물 품질 | P0 정확성·건수 보존·보안·fresh run. 140분 이후 새 기능 금지 |
| **소통** | 배점 미공개, handoff 문서를 만든 사람이 고득점 | 체크포인트마다 handoff를 갱신하고, **새 세션이 문서만으로 이어갈 수 있는지** 한 번 시험한다 |

## 1. 매 프롬프트 — 보내기 전 30초

| 축·세부 | 점검 | 프롬프트 문장 예 |
|---|---|---|
| 의도·작업 분해·위임 | **범위** 한 REQ·한 METHOD 단계만, 손대지 말 파일 명시 | `[REQ-014 / METHOD ③]만. spc.js 외 수정 금지` |
| 의도·Output 목표 구체화 | **완료 모습** 출력 형태·대상·기대값 | `CVD-05 A가 조치, 근거 05:53 표시` |
| 의도·의도 갱신·맥락 유지 | **근거** 정책이면 D-ID 인용, 없으면 질문으로 | `D4·D9 기준으로` |
| 인지·동작·리스크 예측 | **내 예상** 숫자·순위·깨질 테스트 중 하나 | `내 예상: 계측 확인 4건, CVD-05 A만 조치` |
| 의도·검증 루프 설계·통제 | **멈출 조건 + 증거** 테스트 먼저→실패 확인→구현→전체 테스트·exit code | `결정표에 없는 규칙이 필요하면 멈추고 질문 초안` |
| 의도·문제 상황·제약 정의 | **제약** 스택·외부 전송·금지 도구·제출 경로를 어기지 않나 | `표준 라이브러리만, 0.0.0.0 바인딩 유지` |

받은 뒤 30초:
- [ ] **[인지] 예측** 예상과 결과를 대조했다. 다르면 METHOD 단계 번호로 원인을 물었다
- [ ] **[인지] 구조 이해** `git diff --stat`으로 범위를 보고 핵심 함수 하나를 직접 읽었다. 이해를 한 줄로 확인받았다
- [ ] **[인지] 근거 이해** 새 기준값·방식이 나오면 "왜 이 값인가, 대안 1~2개와 결과 차이"를 물었다
- [ ] **[인지] 근거 이해** 결정과 다른 구현이면 D-ID를 근거로 반박하고 되돌렸다
- [ ] **[의도] 맥락 유지** 새 담당자 답은 같은 응답에서 interview Q-ID → decisions D-ID로 기록했다
- [ ] **[기술] 유지보수성** REQ가 통과하면 `REQ-xxx: METHOD ④ 요약 (Dn)`으로 commit했다

## 2. 체크포인트 — 180분 기준 예시

### 0~5분 시작
- [ ] **[의도] 재사용 체계** Git 루트 확인 → `init: 과제 원본` commit → install.py → init_work.py ([GIT](GIT.md))
- [ ] **[의도] 재사용 체계** 과제 폴더에서 Codex 시작, AGENTS 규칙 3개를 말하게 해서 로드 확인
- [ ] **[의도] 제약 정의** 금지 도구·외부 전송·제출 경로·실행 방법을 problem 제약과 state에 기록

### 15분 DISCOVERY 끝
- [ ] **[의도] 목표 구체화** problem: 사용자·해결할 문제·측정 가능한 성공 기준
- [ ] **[의도] 제약 정의** problem: 만들 것·만들지 않을 것·제약·Unknown
- [ ] **[인지] 예측** 데이터를 직접 열어 함정 후보를 내가 먼저 적고, AI 분석과 비교해 서로 놓친 것을 표로
- [ ] **[의도] 맥락 유지** 질문 3~5개를 질문 카드로 보내고 답 원문은 interview에

### 30분 GATE1 합의
- [ ] **[의도] 분해·위임** skeleton ①~⑥ 행마다 입력→출력·함정·D-ID·REQ
- [ ] **[의도] 검증 루프** requirements REQ마다 P0/P1/P2·합격 문장·검증 명령·근거 D
- [ ] **[기술] 요구사항 충족** 담당자 범위 승인과 시각을 state GATE1에 기록, `GATE1:` commit

### 45분 GATE2 첫 결과
- [ ] **[기술] 기능적 정확성** 실제 입력→실제 출력이 한 번 끝까지 나옴
- [ ] **[인지] 예측** 실행 전 예상을 대화에 남기고 결과와 대조
- [ ] **[인지] 구조 이해** "내가 이해한 구조: ①…⑥, 정책 값은 config" 한 줄을 확인받음
- [ ] **[의도] 목표 구체화** 담당자에게 첫 결과를 보여 주고 성공 기준을 재확인
- [ ] **[소통]** handoff 첫 작성: 목표·STATE·실행 명령·다음 3행동, `REQ-001: E2E v0` commit

### 80~90분 구조 동결
- [ ] **[기술] 유지보수성** 단계별 함수, 판정·순위는 순수 함수, 정책 값은 config(+D 연결)
- [ ] **[인지] 구조 이해** 입력→파일:함수→정책→출력을 **내가** 추적해 decisions 예측·추적 칸에 기록
- [ ] **[소통]** handoff·state 갱신: `STATE=VERIFY, METHOD=④, D? 반영 중`

### 115분 VERIFY 끝
- [ ] **[기술] 요구사항 충족** P0 REQ 전부 통과, REQ별 commit
- [ ] **[기술] 기능적 정확성** 정답 사례·경계·회귀·건수 보존식(배타 분류의 합 = 입력) 통과
- [ ] **[기술] 실무적 품질 위험** 오류 행을 버리지 않고 보여 줌, XSS(textContent)·하드코딩 경로·바인딩·비밀값 점검
- [ ] **[의도] 재사용 체계** 같은 프롬프트 틀을 단계마다 재사용했다
- [ ] **[인지] 근거 이해** 주요 기준값마다 "왜·대안"을 물은 흔적이 있다

### 140분 새 기능 동결
- [ ] **[의도] 분해·위임** 새 요청을 설정 변경 / 단계 내부 / 경계 변경으로 분류해 반영·보류
- [ ] **[의도] 맥락 유지** 보류·변경을 새 D와 "대체됨→Dn"으로 기록
- [ ] **[기술] 품질 위험** 읽기 전용 감사 1회: 합의문↔코드↔테스트 대조
- [ ] **[인지] 예측** 한계·장애 시나리오를 내가 먼저 쓰고 AI는 보완만
- [ ] **[기술] 정확성·[인지] 근거** 문서 주장 감사(STAGE_PROMPTS ACC-9) 1회: 근거 없는 문장·대체된 D의 옛 표현·'미정' 잔존 0개

### 155분 GATE3 fresh run
- [ ] **[기술] 제출물 완성도** 새 터미널에서 README_RUN 그대로 실행, 명령·exit code·HTTP 응답 기록
- [ ] **[기술] 제출물 완성도** 과제가 요구한 문서 이름 그대로, 선택 이유·검증·한계 포함
- [ ] **[의도] 검증 루프** state GATE3 기록, `GATE3: fresh run passed` commit
- [ ] **[기술] 완성도** fresh run 뒤 ACC-9 재확인: 문서의 명령·숫자가 방금 실행 출력과 같다
- [ ] **[인지] 서술형 리허설** 예상 질문 5~6개에 직접 답: "왜"는 결론→근거→안 했으면, "장애"는 약점→파급→다음 검증
- [ ] **[소통] 이어받기 시험** 새 Codex 세션에서 "handoff·README_RUN만 읽고 현재 상태와 다음 행동 3개를 말해 줘" → 틀린 곳만 문서 보강

### 170분 제출 직전
- [ ] **[기술] 제출물 완성도** 제출 경로·파일명·저장 상태, 서버 터미널 유지
- [ ] **[인지]** AI 없이 6줄 설명 연습: 구조(①~⑥), 가장 큰 결정(Dn·대안·결과 차이), 어디서 깨지나, 남은 한계
- [ ] **[소통]** handoff 최종: 완료 증거·미결 D·알려진 한계·다음 3행동, 마지막 commit

## 3. 축별 최종 자가 진단 — 155분에 O/X

### ① 기술 관리 — AI 산출물을 내가 장악해 실제로 돌고, 유지 가능하고, 보안이 새지 않나
| 세부 | 평가자가 볼 증거 | 내가 남길 것 | O/X |
|---|---|---|---|
| 코드 유지보수성 | 단계별 함수, 설정 분리, commit 단위 | ①~⑥ 분리, config+D, REQ 단위 commit | |
| 요구사항 충족도 | P0 상태와 검사 로그 | requirements 상태 칸, 테스트 출력 | |
| 기능적 정확성 | 정답 사례·경계·건수 보존 | 담당자 사례 테스트, 보존식 테스트 | |
| 실무적 품질 위험 | 오류 처리·보안 | 격리 목록, textContent, 바인딩, 비밀값 없음, 감사 결과 | |
| 제출물 완성도 | 그대로 실행되는가 | fresh run 기록, 지정 문서·경로 | |

### ② 의도 관리 — 목표·제약을 정의하고, 분해해 위임하고, 검증 루프로 통제했나 (변별력 최대)
| 세부 | 평가자가 볼 증거 | 내가 남길 것 | O/X |
|---|---|---|---|
| Output 목표 구체화 | 측정 가능한 완료 모습 | problem 성공 기준, 프롬프트의 기대값, 시연 후 재확인 | |
| 재사용 가능한 작업 체계 | 같은 틀의 반복, 도구 | kit 설치, 프롬프트 틀 반복, SELFCHECK·status --intent | |
| 의도 갱신 및 맥락 유지 | 바뀐 의도의 추적 | Q→D→REQ 연결, 대체 관계, state·handoff 갱신 | |
| 검증 루프 설계 및 통제 | 테스트 먼저, 멈춤 | 실패 먼저 확인, 멈출 조건, GATE 기록, 테스트 약화 거절 | |
| 문제 상황 및 제약 정의 | 범위 통제 | 만들지 않을 것·제약·Unknown | |
| 작업 분해·위임 설계 | 한 번에 하나 | 프롬프트당 REQ 1개·단계 1개, skeleton | |

### ③ 인지 관리 — 왜 이 구조인지, 어떻게 동작하는지, 어디서 깨지는지 내 산출물로 설명하나 (전원 최저 → 기회)
| 세부 | 평가자가 볼 증거 | 내가 남길 것 | O/X |
|---|---|---|---|
| AI 산출물 동작 및 리스크 예측 | 실행 **전** 예상과 대조 | 프롬프트 속 "내 예상", 예상↔실제 차이, 한계·장애 시나리오를 내가 먼저 | |
| AI 산출물 구조 이해 | 직접 읽은 흔적 | diff 확인, 구조 한 줄 확인, 입력→함수→출력 직접 추적 | |
| AI 의사결정 및 근거 이해 | 왜·대안을 아는가 | "왜 이 값·대안 결과 차이" 질문, D 근거 반박·되돌림, 서술형 6줄 | |

### ④ 소통 — 다른 사람·다른 세션이 자연스럽게 이어갈 수 있나 (FDE 트랙)
| 세부 | 평가자가 볼 증거 | 내가 남길 것 | O/X |
|---|---|---|---|
| 이어받기 문서 | 문서만으로 재개 가능 | handoff: 목표·STATE·완료 증거·미결 D·실행 명령·다음 3행동 | |
| 결정 전달 | 왜 이렇게 했는지 | decisions 표, README의 핵심 결정·한계 | |
| 실행 안내 | 처음 보는 사람이 실행 | README_RUN 설치→실행→검사→오류 대처 | |
| 이어받기 검증 | 실제로 이어지는지 | 새 세션 이어받기 시험 결과와 보강 내역 | |

## 4. 바로 감점되는 행동
- **[의도]** "알아서 다 만들어 줘" 한 방 프롬프트, 담당자 답 요약·지어내기, 미응답을 승인으로 기록
- **[의도·기술]** 테스트가 실패하자 테스트나 기준을 고치게 두기
- **[기술]** 데이터 행 조용히 삭제, 140분 이후 새 기능, 제출 경로 착오, 서버 터미널 종료
- **[인지]** 결과를 읽지 않고 "좋아, 다음" 반복, AI 용어를 이해 없이 서술형에 옮기기
- **[소통]** handoff를 마지막에 한 번에 몰아 쓰기, 문서와 실제 코드·명령이 다름
- **[기술·인지]** 할루시네이션: src에 없는 규칙을 문서에 씀, 바뀐 결정의 옛 문장 잔존, 실행하지 않은 숫자·통과 주장
